
Fix contact sync conflict

Do I know what the issue is? Yes.

Current diagnosis
- The failing path is `SmartPasteContacts -> useUpsertUserContacts -> user_contacts.upsert(...)`.
- The live network trace shows a `POST /rest/v1/user_contacts?on_conflict=owner_id,phone` returning `42P10: there is no unique or exclusion constraint matching the ON CONFLICT specification`.
- `user_contacts` does not currently have real UNIQUE constraints for `(owner_id, phone)` or `(owner_id, email)`.
- It only has partial unique indexes, including both the original pair:
  - `user_contacts_unique_phone`
  - `user_contacts_unique_email`
  and the newer duplicate pair:
  - `user_contacts_owner_id_phone_key`
  - `user_contacts_owner_id_email_key`
- `phone_contacts` is not the culprit here; it already has a real `UNIQUE(profile_id, phone_number)` constraint.

Why the last fix did not solve it
- The last migration added more partial unique indexes on `user_contacts`.
- The upsert generated by the REST layer is using `onConflict: 'owner_id,phone'`, which needs a real matching unique constraint/non-partial conflict target on that table.
- So the request still fails before any row can be inserted or updated.

Implementation plan

1. Database fix for `user_contacts`
- Create one new migration that:
  - drops the four redundant partial indexes on `user_contacts`
  - adds real table-level UNIQUE constraints:
    - `UNIQUE (owner_id, phone)`
    - `UNIQUE (owner_id, email)`
- Keep all existing contacts; no deletion of contact data.
- This is safe because duplicate checks for `(owner_id, phone)` and `(owner_id, email)` currently return no duplicate rows.

2. Hardening `src/hooks/useUserContacts.tsx`
- Keep the UI untouched.
- Normalize incoming data before save:
  - trim `name`
  - lowercase + trim `email`
  - normalize `phone` consistently
- Replace the current “split and blindly upsert” approach with merge-aware saving:
  - fetch any existing `user_contacts` rows for the same owner that match incoming phones or emails
  - if an incoming contact matches an existing row by phone or email, update that row by `id` and merge missing fields
  - only insert/upsert brand-new rows
- Keep the existing split behavior for phone-backed vs email-only records where helpful, but avoid cross-key collisions.

3. Verification
- Re-test the exact failing “Add 1 Contact” Smart Paste flow.
- Re-test CSV, VCF, and device import since they all share `useUpsertUserContacts`.
- Confirm all of the following:
  - no more `42P10` conflict error
  - same phone can be re-imported without failure
  - email-only contacts still save correctly
  - a later import with both phone + email merges into an existing email-only contact instead of failing

Files in scope
- `supabase/migrations/<new migration>.sql`
- `src/hooks/useUserContacts.tsx`

Out of scope

- No changes to auth, squads, events, or styling
